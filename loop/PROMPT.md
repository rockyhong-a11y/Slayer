너는 Godot 4.x 게임 프로젝트 **Slayer**를 한 이터레이션만큼 전진시킨다.
너는 기억이 없는 새 세션이다. 아래 순서를 그대로 따른다.

## 1. 읽기 (반드시 먼저, 이 순서대로)

1. `docs/feedback/INBOX.md` — 사용자 지시. **최우선.** 다른 모든 것을 이긴다.
2. `docs/DESIGN.md` — 무엇을 만드는가. 핵심 루프와 완료 기준(DoD).
3. `docs/STATUS.md` — 지금 위치, 다음 할 일 큐, 함정 목록.

## 2. 이번 이터레이션의 일감 고르기

- INBOX "대기 중"에 항목이 있으면 **그것부터**.
- 없으면 STATUS "다음 할 일 큐"의 **맨 위 하나**.
- **한 이터레이션에 하나만.** 큐를 한꺼번에 비우려 하지 마라.

## 3. 작업

- 요청된 것만 만든다. 추측성 기능·추상화·설정 가능성을 추가하지 마라.
- 밸런스 수치는 `scripts/run_state.gd` 한 곳에 모아 둔다. 흩뿌리지 마라.
- 게임 내 UI 문자열은 ASCII만 쓴다. 기본 폰트에 한글 글리프가 없다 (DESIGN 6).

## 4. 눈으로 확인 (건너뛰지 마라)

화면에 영향을 주는 변경을 했다면 **반드시** 캡처해서 직접 본다:

```bash
tools/capture.sh title    qa_shots/title.png
tools/capture.sh dungeon  qa_shots/dungeon.png
tools/capture.sh combat   qa_shots/combat.png
tools/capture.sh reward   qa_shots/reward.png
```

그리고 생성된 PNG를 **Read 도구로 열어서 실제로 본다.** 파일이 존재하는 것만으로는 통과가 아니다.
검은 화면, 두부 글자(□), 화면 밖으로 잘린 텍스트, 겹친 UI가 보이면 그게 이번 이터레이션의 버그다.
캡처가 실패하면 그 실패를 고치는 것이 이번 이터레이션의 일이다.

## 5. 마무리 (반드시)

1. **`docs/STATUS.md`를 인수인계서처럼 갱신한다.** 다음 세션은 이것만 읽는다.
   - "지금 위치" — 실제 상태로 다시 쓴다
   - "다음 할 일 큐" — 끝낸 항목 제거, 새로 발견한 일 추가
   - "완료 기록" — 이번 이터레이션 한 줄 추가
   - "함정 / 배운 것" — 같은 삽질을 반복하게 만들 만한 것을 남긴다
2. INBOX 항목을 처리했으면 "처리 완료" 표로 옮긴다.
3. 변경을 커밋한다: `git add -A && git commit -m "<무엇을 왜>"`
4. DESIGN.md의 DoD(B1~B5, Q1~Q3)가 **전부** 통과하고 STATUS 큐가 비었으면,
   `loop/STOP` 파일에 멈추는 이유를 적어 생성한다. 그 전에는 절대 만들지 마라.

## 금지

- `docs/DESIGN.md`의 완료 기준을 통과시키려고 **기준 자체를 느슨하게 고치지 마라.**
  기준이 틀렸다고 판단되면 고치지 말고 INBOX에 문제 제기를 적고 넘어가라.
- 검증 없이 "됐다"고 STATUS에 적지 마라. 캡처를 안 봤으면 안 봤다고 적어라.
- 요청받지 않은 리팩터링, 무관한 코드 정리.
