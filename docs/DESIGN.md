# DESIGN — 무엇을 만드는가

> 이 문서는 "무엇을 만드는가"만 담는다. 지금 어디까지 했는지는 `docs/STATUS.md`,
> 사용자 지시는 `docs/feedback/INBOX.md`에 있다.

## 1. 한 줄 정의

**Slayer** — Godot 4.x로 만드는 **로그라이크 던전 크롤러**.
한 판(run)은 짧고, 죽으면 처음부터. 매 판마다 다른 선택이 쌓여 빌드가 갈린다.

## 2. 핵심 루프

```
탐험 → 전투 → 보상 → 다음 방 → (반복) → 사망 or 클리어 → 처음부터
```

| 단계 | 플레이어가 하는 일 | 화면 (`GAME_START` 키) |
|---|---|---|
| 탐험 | 다음 방에 무엇이 있는지 보고 진입 | `dungeon` |
| 전투 | 공격을 주고받아 적을 처치 | `combat` |
| 보상 | 3개 중 1개 선택 (최대체력 / 공격력 / 회복) | `reward` |
| 클리어 | 10방을 다 깬 결과를 보고 타이틀로 돌아감 | `victory` |
| 시작·사망 | 판 시작과 리셋 | `title` |

한 판의 목표 길이: **10방**. 한 판 플레이 시간 목표: **3~5분**.

## 3. 지금의 규칙 (스켈레톤 수치)

루프가 고쳐 나갈 출발점이다. 확정값이 아니다.

- 플레이어 시작: `HP 30`, `ATK 6`
- 방 `n`의 적: `HP = 10 + n*4`, `ATK = 2 + n`
- 전투: 한 번의 교환마다 플레이어가 먼저 때리고, 적이 살아 있으면 반격. 데미지 변동 `±1`
- 보상 3종: `+8 최대체력(+8 회복)` / `+2 공격력` / `12 회복`

수치는 모두 `scripts/run_state.gd` 한 곳에 모여 있다. 밸런스를 만질 때 여러 파일을 뒤지지 않게 하기 위한 의도이며, 이 성질을 깨지 말 것.

## 4. "이 정도면 됐다" — 완료 기준 (DoD)

사용자가 제시한 기준은 **"밸런스가 말이 됨"** 하나다.
그대로는 루프의 정지 조건이 될 수 없어, 아래처럼 **측정 가능한 수치로 번역**했다.

> ⚠️ **아래 수치 밴드는 사용자가 지정한 값이 아니라, 로그라이크 통념에 기반한 제안이다.**
> 동의하지 않으면 `docs/feedback/INBOX.md`에 고쳐 적을 것. INBOX가 이 문서를 이긴다.

자동 시뮬레이션 **100판** 기준:

| # | 항목 | 통과 기준 | 이유 |
|---|---|---|---|
| B1 | 10방 클리어 승률 | **30% ~ 50%** | 너무 쉬우면 긴장이 없고, 너무 어려우면 학습이 안 된다 |
| B2 | 평균 사망 방 번호 | **5 ~ 9** | 초반에 몰려 죽으면 판이 시작도 못 하고 끝난다 |
| B3 | 1~2방 사망률 | **5% 미만** | 즉사 구간이 없어야 한다 |
| B4 | 무피해 10방 클리어율 | **2% 미만** | 무적 빌드가 없어야 한다 |
| B5 | 보상 3종 선택 승률 편차 | 한 선택지가 **80% 이상 지배하지 않음** | 지배 전략이 있으면 선택이 선택이 아니다 |

추가로, 밸런스와 무관하게 항상 참이어야 하는 것:

| # | 항목 | 통과 기준 |
|---|---|---|
| Q1 | 한 판 완주 | 시작 → 전투 → 사망/클리어까지 끊김 없이 진행 |
| Q2 | 런타임 에러·경고 | Godot 콘솔에 에러 0, 경고 0 |
| Q3 | 시각 QA | `title/dungeon/combat/reward` 4장 캡처가 모두 성공하고, 각 화면에 필요한 정보(HP·방 번호·적·조작 안내)가 잘림 없이 보임 |

**루프 정지 조건:** B1~B5와 Q1~Q3가 전부 통과하고 `docs/STATUS.md`의 "다음 할 일" 큐가 비면,
`loop/STOP` 파일을 만들고 멈춘다.

## 5. 범위 밖 (지금은 만들지 않는다)

요청이 없는 한 손대지 않는다. 추가하고 싶으면 INBOX를 통해 들어와야 한다.

- 세이브/로드, 메타 프로그레션, 해금
- 멀티플레이, 네트워크
- 사운드, BGM
- 모바일 빌드, 플랫폼 이식
- 절차적 맵 생성 (방은 당분간 일직선)

## 6. 알려진 제약

- **한글 폰트 없음** — Godot 기본 폰트에 한글 글리프가 없어 게임 내 UI 문자열은 전부 ASCII다.
  한글을 쓰려면 폰트를 먼저 프로젝트에 넣어야 한다. 그 전까지 한글을 쓰면 캡처에 두부(□□□)로 찍힌다.
- **플레이스홀더 아트** — 캐릭터와 적은 `ColorRect` 사각형이다.
- **코드로 만든 UI** — 현재 화면들은 `.tscn`에 루트만 있고 자식은 스크립트가 만든다.
  UI가 복잡해지면 `.tscn`으로 옮기는 게 맞다.
